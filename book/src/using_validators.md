# Attach validators

Add validators and field modifiers inside one `#[koruma(...)]` attribute, then derive `Koruma`
on the containing struct. Calling `validate()` runs every applicable rule and returns typed
failures grouped by field.

## Configure a validator

Use the dot-chain setters generated by `#[validator]`:

```rust,ignore
#[koruma(NumberRangeValidation::<_>.min(0).max(100))]
```

Koruma supplies the validated value and completes the builder. Inside `#[koruma(...)]`, omit
`::builder()`, `.with_value(...)`, `.capture_value_ref(...)`, and `.build()`.

Put generic arguments on the validator path, not a setter, and pass one expression to each setter.
Use `TypeName::<_>` for a zero-configuration generic validator. Fields without a
`#[koruma(...)]` attribute are ignored on regular structs; use `#[koruma(skip)]` when an
explicit marker improves readability.

## Select optional targets

A validator on `Option<T>` receives `&T` for `Some(T)` and is skipped for `None` by default.
Use an explicit `Option<_>` validator type or `full(...)` when the rule must inspect the whole
option:

```rust,ignore
#[koruma(koruma_collection::general::RequiredValidation::<Option<_>>)]
pub display_name: Option<String>;

// Equivalent explicit target selection:
#[koruma(full(koruma_collection::general::RequiredValidation::<_>))]
pub nickname: Option<String>;
```

Use `unwrapped(...)` only when you want to state the default target explicitly:

```rust,ignore
#[koruma(unwrapped(NumberRangeValidation::<_>.min(0).max(100)))]
pub optional_score: Option<i32>;
```

## Label repeated validators

Two validators with the same final type need lower-snake labels so their generated names do not
collide. Labels are also useful when a domain name is clearer than a validator type name:

```rust,ignore
#[koruma(
    adult_range = NumberRangeValidation::<_>.min(18).max(120),
    working_range = NumberRangeValidation::<_>.min(18).max(67),
)]
pub age: i32;
```

The generated accessors are `adult_range()` and `working_range()`; the corresponding `all()`
variants are `AdultRange` and `WorkingRange`. Labels use the same syntax inside `each(...)`.

## Inspect field failures

For a type named `Item`, `validate()` returns
`Result<(), ItemKorumaValidationError>`. Each direct validator has a snake-case accessor, and
`all()` iterates every stored direct-validator failure:

```rust,ignore
use koruma::{Koruma, KorumaAllDisplay};

#[derive(Koruma, KorumaAllDisplay)]
pub struct Item {
    #[koruma(NumberRangeValidation::<_>.min(0).max(100))]
    pub age: i32,

    #[koruma(StringLengthValidation.min(1).max(67))]
    pub name: String,

    pub internal_id: u64,
}

let item = Item {
    age: 150,
    name: String::new(),
    internal_id: 1,
};

if let Err(errors) = item.validate() {
    if let Some(error) = errors.age().number_range_validation() {
        println!("age failed: {error}");
    }

    for error in errors.name().all() {
        println!("name failed: {error}");
    }
}
```

Koruma evaluates every validator for a present target rather than stopping at the first failure.
The `all()` iterator borrows stored validators in source order.

## Validate collection elements

Use `each(...)` with `Vec<T>`, borrowed slices, arrays, and optional forms of those types:

```rust,ignore
#[derive(Koruma)]
pub struct Order {
    #[koruma(each(NumberRangeValidation::<_>.min(1).max(5)))]
    pub quantities: Vec<i32>,
}
```

Collection recognition is syntactic. Type aliases and custom collection types are not expanded,
and a recognized `Vec<T>` path must resolve to `std::vec::Vec<T>`.

Element failures are separate from validators on the collection itself. Inspect the index and then
the element's typed error container:

```rust,ignore
let order = Order {
    quantities: vec![1, 8, 3],
};

if let Err(errors) = order.validate() {
    for (index, element_errors) in errors.quantities().element_errors() {
        if let Some(error) = element_errors.number_range_validation() {
            println!("quantities[{index}]: {error}");
        }
    }
}
```

See [Handle validation errors](error_handling.md) for generic issue enumeration and rendering
choices.
