# koruma-core

[![Docs](https://docs.rs/koruma-core/badge.svg)](https://docs.rs/koruma-core/)
[![Crates.io](https://img.shields.io/crates/v/koruma-core.svg)](https://crates.io/crates/koruma-core)

Core traits and types for the `koruma` validation ecosystem. Most users should depend on
`koruma` instead of this crate directly.

## What it provides

- `Validate<T>`: implemented by validator structs.
- `ValidatorMetadata<T>`, `ValidatorDescriptor`, `ValidatorParamDescriptor`,
  `ValidatorParam`, and `ValidatorParamValue`: optional metadata for tooling
  that needs validator type and parameter information without changing
  `Validate<T>`.
- `ValidationError`: implemented by generated error structs.
- `ValidationIssues`, `ValidationIssue`, `ValidationIssueScope`, and
  `ValidationFieldName`: optional structured issue enumeration implemented by
  generated error structs.
- `ValidateExt`: used for nested/newtype validation; handwritten implementations
  must use an error type that implements `ValidationError + Default`.
- `NewtypeValidation`: marker for newtype structs with transparent error access.
- `NewtypeValue`: borrow, consume, or validate the inner value of a validated
  newtype without relying on a public wrapper field.
- `NewtypeTryFromInner`: validate and reconstruct a newtype from its inner
  value.

Validator builders generated by `#[koruma::validator]` expose an inherent
`with_value(...)` method when a validator captures the validated value. Derived
validation uses an internal borrowed-value hook, so most users should not need
builder traits directly.

## Features

- `fluent`: enables hidden Fluent assertion hooks used by generated code and
  Fluent-aware showcase rendering.
- `internal-showcase`: enables the type-erased showcase registry used by
  workspace demos.
