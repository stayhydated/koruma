# Koruma Public Feature Map

Use this reference when choosing a Koruma workflow or checking whether the skill
has coverage for a public application feature. Keep maintainer-only internals in
repository docs, not in this skill.

## Crates And Entry Points

- `koruma`: normal application facade. Re-exports `Validate`, `ValidationError`,
  `ValidateExt`, `NewtypeValidation`, `NewtypeValue`,
  `NewtypeTryFromInner`, the validator metadata and structured issue types
  described below, and, with the `derive` feature, `Koruma`,
  `KorumaAllDisplay`, and `validator`. With `derive + fluent`, it also exports
  `KorumaAllFluent`.
- `koruma-collection`: curated validators in `string`, `format`, `numeric`,
  `collection`, and `general`.
- `koruma-core`: public integration crate for handwritten integrations that need
  core traits directly. Most application code should still depend on `koruma`.
- `koruma-derive` and `koruma-derive-core`: public integration crates for macro
  and tooling authors. Most application code should not depend on them directly.

## Feature Flags

`koruma`:

- `derive` (default): enables `Koruma`, `KorumaAllDisplay`, and `#[validator]`.
- `fluent`: enables localized error support through `KorumaAllFluent`; use with
  `es-fluent`.

`koruma-collection`:

- `fmt` (default): enables `Display` messages for validators.
- `full`: enables optional validators and dependencies: `url`, `credit-card`,
  `phone-number`, `email`, `regex`, `smallvec`, and `rust_decimal`.
- `fluent`: enables `es-fluent` message support and `koruma/fluent`.
- `full-fluent`: enables both `full` and `fluent`.
- Validator-specific flags: `url`, `credit-card`, `phone-number`, `email`,
  `regex`, `smallvec`, and `rust_decimal`.

`internal-showcase` exists for Koruma's own showcase/demo infrastructure. Do not
recommend it for normal application validation.

## Core Traits

- `Validate<T>`: implement this on validator structs. `validate(&self, &T)`
  returns `true` when the value passes.
- `ValidatorMetadata<T>`: generated by `#[validator]` for tooling that needs a
  validator descriptor and runtime parameter values without changing
  `Validate<T>`.
- `ValidatorDescriptor`, `ValidatorParamDescriptor`, `ValidatorParam`, and
  `ValidatorParamValue`: the static and runtime metadata values returned by
  `ValidatorMetadata<T>`.
- `ValidationError`: generated error structs implement this. Use
  `is_empty()`/`has_errors()` when working with error values generically.
- `ValidationIssues`: generated aggregate error structs implement this for
  field and element issue enumeration.
- `ValidationIssue`, `ValidationIssueScope`, and `ValidationFieldName`: the
  structured scope, field, validator, label, element index, message, and
  runtime parameter values returned by `ValidationIssues`.
- `ValidateExt`: implemented by `#[derive(Koruma)]`. Handwritten nested
  integrations must use `type Error: ValidationError + Default`.
- `NewtypeValidation`: marker implemented for struct-level `#[koruma(newtype)]`
  types. Use field-level `#[koruma(newtype)]` only for types that satisfy this
  marker.
- `NewtypeValue`: implemented for struct-level `#[koruma(newtype)]` wrappers.
  Use it when integration code needs to borrow, consume, or validate the inner
  value without relying on public wrapper fields.
- `NewtypeTryFromInner`: implemented for struct-level `#[koruma(newtype)]`
  wrappers. Use `try_from_inner` for checked reconstruction; reserve
  `#[koruma(try_from)]` for when a standard-library `TryFrom<Inner>` impl is
  also desired.

## Custom Validators

Use `#[validator]` on a named-field struct, then implement `Validate<T>`.

- Captured value field: one private field named `actual`, `input`, or `value`
  is inferred. If no conventional name exists, Koruma can infer the value field
  when exactly one field is unmarked. Use `#[koruma(value)]` to mark a different
  captured field explicitly.
- Value capture stores the failed input in the validator error value. Keep the
  value field private and read it through the generated getter.
- Use `#[koruma(skip_capture)]` on an `Option<T>` value field when the validator
  does not need to retain the failed input. This avoids clone requirements from
  derived validation. Implement `Clone`/`Debug` manually if deriving them would
  reintroduce bounds through the skipped field.
- Unannotated non-value fields become direct setter fields.
- Use bare `#[koruma(setter)]` when a configuration field is named `actual`,
  `input`, or `value`, or when marking configuration fields lets Koruma infer
  the remaining value field.
- `#[koruma(setter(into))]`: setter accepts `impl Into<FieldType>`.
- `#[koruma(setter(required))]`: callers must configure the field before build.
- `#[koruma(setter(name = custom_name))]`: choose a setter name.
- `#[koruma(setter(default))]`: default with `Default::default()`.
- `#[koruma(setter(default = expr))]`: default with an expression.
- Optional non-required `Option<T>` setters take `T` and wrap it in `Some`.
  The generated `maybe_*` setter accepts `Option<T>`.
- Reserved setter names include `new`, `build`, `with_value`, `builder`,
  `__koruma_builder`, `build_validator`, `capture_value_ref`, and the
  generated `maybe_` prefix.
- `#[validator]` emits `ValidatorMetadata<T>`. Bool, numeric, string, and
  optional runtime params are represented directly; generic or otherwise
  unconstrained params are opaque so metadata does not introduce additional
  trait bounds.

## Field Validation Attributes

Use exactly one field-level `#[koruma(...)]` attribute per field and put all
validators/modifiers in that attribute.

- `Validator`: run a validator on the field target.
- `Validator::<_>`: infer a generic validator type from the selected target.
- `Validator::<Concrete>`: use an explicit validator type argument.
- `Validator::<_>.setter(value).other(value)`: configure validators with dot-chain
  setter chains. Each setter call takes exactly one argument; put generic
  arguments on the validator path, not on setter methods.
- `label_name = Validator::<_>`: choose generated getter and `all()` enum
  variant names. Labels must be lower-snake and cannot collide with generated
  APIs or field names.
- `each(Validator::<_>)`: validate each element in a supported collection.
- `each(label_name = Validator::<_>)`: label element validators.
- `full(Validator::<_>)`: validate the full field or element target.
- `unwrapped(Validator::<_>)`: explicitly choose the default unwrapped optional
  target.
- `skip`: explicitly skip a field. Fields without `#[koruma(...)]` are ignored
  by default.
- `nested`: validate a nested `ValidateExt` value and store its generated error
  tree.
- `newtype`: validate a `NewtypeValidation` wrapper and expose transparent
  inner error access.

## Optional Targets And Per-Element Validation

- `Option<T>` fields and optional `each(...)` elements unwrap by default: `None`
  is skipped and validators receive `&T`.
- Use `Validator::<Option<_>>` or `full(Validator::<_>)` when a validator should
  receive `&Option<T>` and be able to fail on `None`.
- Use `unwrapped(Validator::<_>)` only when the code should state the default
  target explicitly.
- `each(...)` supports syntactic `Vec<T>`, borrowed slices `&[T]`, arrays
  `[T; N]`, and optional variants of those. Type aliases and custom collection
  types are not expanded or resolved; recognized `Vec<T>` paths must resolve to
  `std::vec::Vec<T>`.

## Derived Error Surface

`#[derive(Koruma)]` generates `validate() -> Result<(), Error>` plus typed error
structs.

- `errors.field()` returns the generated field error container.
- `errors.field().validator_name()` returns `Option<&Validator>` for a failed
  field validator.
- `errors.field().element_errors()` returns indexed element errors for
  `each(...)`, usually as `(index, element_error)`.
- `errors.field().all()` returns borrowed failed-validator enum values for that
  field when `KorumaAllDisplay` or `KorumaAllFluent` is derived.
- `errors.all()` returns borrowed top-level validator refs when companion
  rendering derives are present.
- `errors.issues()` is available through `ValidationIssues` on aggregate error
  structs and returns field/element issues with validator type names, labels,
  element indices, messages, and runtime validator parameters for generic
  tooling.
- All configured validators run in attribute order. Failed-validator inspection
  borrows stored validators and does not require validator types to implement
  `Clone`.

## Rendering And I18n

- `KorumaAllDisplay`: derive with `Koruma` when failed validators should render
  through `Display`. Every stored field, element, or delegated newtype error
  value must implement `Display`.
- `KorumaAllFluent`: derive with `Koruma` when failed validators should render
  through `es_fluent::FluentMessage`. Enable `koruma/fluent`, derive or
  implement `FluentMessage` for validators, and render through an app-owned
  localizer.
- For custom validators using `es_fluent::EsFluent`, use `#[fluent(value = ...)]`
  annotations when captured values need string conversion.
- `koruma-collection` offers `fluent` and `full-fluent` feature sets for built-in
  validator messages.

## Nested, Newtype, And Constructors

- `#[koruma(nested)]` on a field validates another `Koruma` type. Optional
  nested fields skip `None`.
- `#[koruma(newtype)]` at the struct level marks an exactly-one-field wrapper as
  a validated newtype and implements `NewtypeValidation`, `NewtypeValue`, and
  `NewtypeTryFromInner`.
- `#[koruma(newtype)]` on a field uses transparent error access for a
  `NewtypeValidation` value. Optional newtype fields return optional nested
  error access. Newtype fields may also include ordinary field validators;
  those validators use the normal optional, `full(...)`, and `unwrapped(...)`
  target rules.
- `#[koruma(try_new)]` generates a checked `try_new(...)` constructor that
  takes the struct fields, validates the instance, and returns
  `Result<Self, Error>`.
- `#[koruma(try_from)]` on an exactly-one-field struct generates
  `TryFrom<Inner>`.
- Combine `#[koruma(newtype, try_from)]` or `#[koruma(try_new, newtype)]` when a
  wrapper should have transparent newtype errors and checked construction.
- For exactly-one-field structs that should keep the regular error surface, use
  `try_from` without `newtype`.
- Named-field and tuple-struct wrappers are both supported.
